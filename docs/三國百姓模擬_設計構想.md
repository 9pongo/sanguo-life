# 三國百姓模擬：設計構想

> 狀態：構想階段，**不放進《黃天之下》**。等《黃天之下》的個人故事機制經過更多玩家回饋、穩定之後，再決定要不要做、怎麼做。
> 日期：2026-10-22

## 一、要做的是什麼

一個可以在三國時代「從底層生活」的模擬遊戲。不是戰棋、不是經營，而是像《模擬市民》那樣：玩家住在一個村子裡，身邊的每個人都有自己的人生，大事從遠方傳來，落在每個人身上的樣子都不一樣。

跟《黃天之下》的差別：

| | 黃天之下 | 這個構想 |
|---|---|---|
| 主角 | 一個家族，一代一代傳 | 一個里裡面的所有人，玩家是其中一個 |
| 別人 | 名字與一句話（配偶、朋友） | 每個人都有完整的一生，彼此互相影響 |
| 時間 | 一年一格 | 季或月一格，大事照年 |
| 存檔 | 種子＋選擇，重播 | 世界快照（需要資料庫或大型本機儲存） |

### 實際人口

三國戶籍加起來不到一千萬，但豪族的部曲與佃客、屯田民、士家（軍戶）、逃入山中的人（山越、黑山）、邊疆民族大多不在戶籍上。學者推估多在 **2,000 萬到 3,000 多萬** 之間。

**設計上的意義**：「在不在戶籍上」本身就是重要的身分差別。編戶要交租調、服役；蔭附在豪族下的人不必見官府，但生死由莊主決定。

### 漢代基層組織（可直接當成遊戲的層級）

| 單位 | 規模（制度上的約數） |
|---|---|
| 里 | 約百戶，五百人上下 |
| 亭 | 約十里 |
| 鄉 | 約十亭 |
| 縣 | 數鄉，萬戶以上稱令、以下稱長 |

> 實際規模各地差很多，戰亂後的里常常只剩幾十戶。

## 三、分層細緻度：不模擬兩千萬人

《黃天之下》的引擎跑一個人的一生約幾毫秒。在瀏覽器裡逐一模擬兩千萬人要好幾天，而且玩家一輩子遇不到其中 99.99% 的人。所以做法是：**沒人看的地方只算統計，有人看的地方才算到個人。**

| 層級 | 規模 | 模擬方式 |
|---|---|---|
| 天下、州郡 | 數千萬人 | 只有統計：人口、糧價、戰亂、疫病、徵兵壓力，由史實大事推動 |
| 縣、鄉 | 數萬人 | 有名有姓的豪族、官吏、塢主；地方大事（盜賊、修渠、徵調） |
| **里** | **約 500 人** | **每個人都有完整人生**，玩家生活的地方 |
| 家 | 十幾人 | 跟《黃天之下》一樣細 |

**運算預算**：一個里 500 人 × 120 年 ≈ 6 萬人年。照目前引擎的速度，瀏覽器幾秒內可算完。鄰近幾個里可以用較粗的模擬（只算家長與重大事件）。

## 四、程序生成與固定種子

- 每個里、每個家族、每個人都由固定種子生成：`種子(州, 縣, 鄉, 里, 家, 人)`。
- 玩家沒去過的地方不必事先算；走過去的那一刻，用同一顆種子把那裡「長出來」，看起來就像一直都存在。
- 已經被玩家改變過的地方，才需要存下差異（見第九節）。
- 《黃天之下》已經驗證過：同一顆種子永遠長出同一段人生，存檔可以只存種子與選擇。

## 五、人物與關係

每個人（簡化欄位）：

- 基本：姓名、性別、生年、家世、戶籍身分（編戶、佃客、部曲、士家、屯田民、流民）
- 數值：武、文、德、名、財、健（沿用）
- 人生：重心、路線、旗標、傷病、往事
- **關係**（新增，是核心）：
  - 親屬：父母、配偶、子女、兄弟姊妹、宗族
  - 社會：鄰居、玩伴、師徒、主佃、恩怨（誰欠誰、誰救過誰、誰告過誰）
  - 每條關係有強度與「記得的事」，例如「災年他借過我一斗米」

「記得的事」就是《黃天之下》的往事與祖上傳說，從家族內部擴大到人與人之間。

## 六、事件系統的擴充

沿用《黃天之下》資料驅動的事件卡（`req`、`eff`、`choices`、`textIf`、`outIf`），新增：

1. **角色可替換的事件**：事件裡寫 `{甲}`、`{乙}`，條件挑出合適的兩個人，例如「{甲}家缺糧，去找{乙}家借」。同一張卡可以發生在任何兩戶之間。
2. **共享的世界事件**：一場蝗災、一次徵兵同時影響整個里，每戶依自己的條件反應，而不是各自擲骰。
3. **因果鏈**：A 去年沒借糧給 B，今年 B 不幫 A 修堤。需要關係與「記得的事」支撐。
4. **大事傳播**：天下大事以「消息」的形式往下傳，到每個里的時間、版本可能不同（「聽說」）。
5. **視角**：同一件事，對當事人、旁觀者、聽說的人各有一段文字。

## 七、時間粒度

- 大事照年（史實錨點不變）。
- 日常改成季或月：播種、收成、繳租調、服役、婚喪、市集。
- 內容量會成倍增加，所以日常事件要以「可替換角色」與「依處境換寫法」為主，不能每件都手寫。

## 八、玩家身分

- **投胎到任一代、任一支**：先生成一個姓氏三、四代的族譜，再讓玩家成為其中某一支的某個人，可以是嫡長、旁支、庶出、過繼、甚至是蔭附在別人家的佃客。
- 祖上的故事已經寫了一半：家裡的傳說、仇家、欠下的人情，都在玩家出生時就存在。
- （待決）是否允許玩家在死後換成里中其他人繼續，而不只是自己的子女。

> 《黃天之下》先試做其中最簡單的一步：投胎時可能不是第一代，而是某個家族的後代，祖上幾代的人生是真的跑過一遍的。

## 九、存檔與資料（需要往後延的部分）

- 《黃天之下》只存「種子＋玩家的選擇」，接續時重播，一個家族幾百條紀錄、幾毫秒就能重建。
- 一個里 500 人互相影響，重播成本與「玩家改變了別人」的差異量都會變大，需要：
  - 世界快照（每隔一段時間存一份完整狀態）
  - 差異紀錄（玩家造成的改變）
  - 本機用 IndexedDB；跨裝置或多人共享就需要伺服器與資料庫
- 這是成本最高、最該延後的部分。

## 十、內容生產與稽核

- 586 張事件卡只撐得起「一個人的一生，每次玩有點不同」。
- 擴大以後，**自動稽核比內容本身更重要**：人越多，前後矛盾越多。《黃天之下》已有的檢查（父母生死、配偶、孩子、命名避諱、地區與時代、重複的事件、不可能達成的結局）都要沿用，並新增：
  - 兩個人對同一件事的記憶不能矛盾
  - 關係的兩端要一致（A 是 B 的佃客 ⇔ B 是 A 的莊主）
  - 同一個里同一年的共享事件，每戶的反應要合理
- 讀檔法（挑一個家族從頭讀到尾）同樣適用，改成「挑一個里，讀某一年每一戶發生了什麼」。

## 十一、從《黃天之下》可以沿用的部分

| 可沿用 | 需要改寫或新增 |
|---|---|
| 資料驅動的事件卡、條件、效果 | 角色可替換的事件 |
| `textIf`／`outIf` 依處境換寫法 | 人與人的關係與記憶 |
| 固定種子、可重現 | 共享世界狀態、季／月時間格 |
| 地區、家世、勢力、接班、家譜 | 世界快照存檔 |
| 祖上傳說、往事、結局冊 | 多人視角的文字 |
| 自動稽核與大量模擬 | 關係一致性的稽核 |

## 十二、風險與待決問題

1. **相似性**：大多數百姓的一生很像。差異要靠地點、家族、身分、人與人之間的因果，而不是靠事件數量。
2. **節奏**：月份制很容易變成重複勞動，要想清楚玩家每個月「做什麼決定」。
3. **玩家的位置**：玩家是一個人，還是可以俯瞰整個里？
4. **史料的密度**：越往基層，史料越少，需要更多合理推想，要清楚標示哪些是史實、哪些是推想（沿用「史」字小注）。
5. **規模的誘惑**：先做一個里、三十年、一百戶的原型，確定好玩再擴大。

## 十三、建議的里程碑（等《黃天之下》告一段落之後）

1. **原型**：一個里、約一百戶、三十年（例如 184–214），每戶只有家長有完整人生，其他人簡化。驗證「人與人之間的因果」好不好玩。
2. **擴充**：所有人都有完整人生；加入共享世界事件與恩怨。
3. **時間**：加入季節循環與日常事件。
4. **存檔**：快照與差異紀錄（本機）。
5. **世界**：多個里、鄉、縣，分層細緻度。
6. （更後面）跨裝置、多人共享。

## 十四、NPC 對話（AI）

> 參考：ijun-ai「AI 古人聊天室」Skill（人設卡、離線劇本庫、防出戲提示詞的三段式做法），以及景區演員扮李白、依遊客的話當場出口成詩的短影片（只看了標題，沒看到畫面）。共同點是：**玩家說一句，歷史人物用自己的身分當場回一句**。

### 原則

1. **人設卡**：每位可對話的人物一張卡，包含自稱、口吻、常用典故、交好與結仇的人、代表作。人物在不同年份的處境不同，所以人設卡要分時期，例如劉備在 201 年寄居新野，在 214 年已經入蜀。
2. **離線劇本加 AI 雙軌**：先有一份手寫的對話劇本（依時期、交情、玩家身分換寫法），沒有 AI、沒網路、或不想花錢時照樣能聊。AI 即時回應是加分，不是必要。
3. **只說不改**：對話不改變數值、旗標、劇情。改變狀態的仍然是事件卡。這樣存檔碼重播出來的那一局才會一模一樣，稽核也照樣有效。對話紀錄可以留在畫面上，但不寫進存檔、不參與重播。
4. **防出戲**：
   - 人物只知道「現在這一年以前」的事。年表資料只給到當年，提示詞也明講「不知道之後的事」。
   - 不用現代詞彙。玩家故意問現代的東西，要在角色裡帶過去，例如「老夫不知此為何物」。
   - 回應很短（建議 80 字以內），文白相間但讀得懂。
   - 生成後做一次檢查：有沒有出現當年以後的人名、年號、事件，長度有沒有超過。不合格就重試一次，再不行就改用離線劇本。
5. **金鑰與費用**：公開網站不能把 AI 金鑰放在網頁裡，需要一個轉接伺服器，並限制每人每天的次數。claude.ai 的作品頁面可以讓網頁直接問 Claude、不用自己的金鑰，適合先做原型。
6. **一致性的稽核**：手寫劇本照現在的方式稽核。AI 的回應很難全面稽核，所以要準備每位人物各幾十個測試問題（包括故意誘導出戲的），每次改提示詞都跑一遍。

## 附：《黃天之下》「與歷史人物說幾句」構想

> 狀態：構想，還沒做。等第一輪試玩回饋處理完再決定。

### 對象與時機

七位可結交的人物：劉備、曹操、孫堅、諸葛亮、關羽、姜維、嵇康。

- 交情到「相識」以上，在跟這位人物有關的事件卡之後，多一個「說兩句」的選擇。
- 每位人物每一章最多一次，避免打斷節奏。
- 人物已經過世（例如孫堅 191 年、關羽 219 年、嵇康 263 年）就不能再聊，可以改成「到墳前說幾句」，只有離線劇本。

### 玩家怎麼說

- 先給三、四個現成的話頭：問天下大勢、說說家裡的事、請教一件事、敬一杯酒。
- 有 AI 時，再開放自己打字，這就是短影片裡「當場回應」的樂趣。

### 人物知道什麼（餵給 AI 的資料）

- 現在的年份、年號、這位人物當年在哪裡、做什麼（依年表）
- 玩家是誰：名字、性別、年紀、籍貫、家世，第幾代
- 兩人的交情階段，以及一起經歷過的事（從旗標轉成一兩句話，例如「長坂那天你跟著他」）
- 玩家家裡最近的大事（喪偶、添丁、搬家）
- **不給**：當年以後的史實

### 每位人物的招牌

| 人物 | 口吻與招牌 |
|---|---|
| 劉備 | 謙和、念舊，常提「百姓」「漢室」，說到傷心處會落淚 |
| 曹操 | 豪氣、多疑、愛開玩笑，興致來了吟幾句自己的詩（要注意寫作年代） |
| 孫堅 | 直爽、好勇，講話短，三句不離打仗 |
| 諸葛亮 | 謹慎、愛講道理，年輕時自比管仲樂毅，愛唱〈梁父吟〉 |
| 關羽 | 傲氣、重義，讀《春秋》，話少 |
| 姜維 | 隴西口吻，忠於丞相遺志，講到北伐就停不下來 |
| 嵇康 | 放達、不拘禮，談琴、談養生，看不起權貴；可以即興幾句詩或一段琴話，最接近短影片裡的「出口成詩」 |

### 做法與順序

1. **只做離線劇本**：先做一位人物（建議諸葛亮或嵇康），十幾段手寫對話，依時期和交情換寫法（沿用 `textIf`）。放進現在的遊戲、照常稽核。先確認「說兩句」放在哪裡、節奏對不對。
2. **在 claude.ai 版接上 AI**：同一位人物、只有現成話頭、不開放打字。驗證防出戲的提示詞和事後檢查。
3. **開放打字**，加上誘導出戲的測試題。
4. 擴充到七位人物。
5. 如果要在 GitHub Pages 版也有 AI，再處理轉接伺服器、次數限制與費用。

### 風險

- AI 說出跟遊戲劇情矛盾的話，例如說錯玩家跟他的過去。對策是只給確定的資料，並要求「不確定就含糊帶過」。
- 費用與濫用：一定要有次數上限。
- 評分難：好不好玩、像不像，需要真人試玩回饋，不能只靠自動檢查。
