# 黃天之下

投胎到東漢末年，一代一代活下去：從中平元年（184）黃巾起事，一路到光熙元年（306）八王之亂。一個人死了，由子女或弟妹接下這個家；香火斷了，這一家的故事才算完。

**線上試玩：<https://9pongo.github.io/sanguo-life/>**

## 檔案

| 檔案 | 用途 |
|---|---|
| `engine.js` | 遊戲引擎（瀏覽器和 Node 共用），不含任何劇情 |
| `ui.html` | 介面。打包時把引擎和資料塞進來 |
| `load.js` | 讀取並合併 `data/` 底下的資料 |
| `data/world.json` | 世界設定：章節、年號、地區、家世、天賦、死亡率、傳承規則、後記 |
| `data/events_*.json` | 事件卡（主線、羈絆、隨機小事、第二到第八章） |
| `data/endings.json` | 結局（章末與身故），由上往下找第一個符合的 |
| `sim.js` | 稽核與模擬：靜態檢查、執行時一致性檢查、統計報告 |
| `build.js` | 先跑稽核，再打包成 `dist/index.html`（發佈用）與 `dist/dev.html`（本機預覽用） |

## 工作流程

```bash
node sim.js 10000     # 稽核＋模擬一萬條人生，報告寫到 reports/sim_report.md
node build.js         # 打包；稽核有錯誤或頁面腳本有語法錯誤時不會產生檔案
```

推送到 `main` 以後，GitHub Actions（`.github/workflows/pages.yml`）會自動跑稽核與打包，把 `dist/dev.html` 發佈成 GitHub Pages 的首頁。稽核有錯誤時不會發佈。

分享連結時的預覽（標題、簡介、封面圖）寫在 `build.js` 產生的 `dev.html` 開頭；封面圖是 `assets/cover.png`（1200×630）。封面上的事件卡、結局數是畫死在圖裡的，數量變很多時記得重畫。

本機預覽請開 `dist/dev.html`（有完整的 doctype、charset、viewport）。`dist/index.html` 是給發佈平台用的，平台會自動補外框。

目標是每次修改後 **錯誤 0、提醒 0**。

## 事件卡

```json
{
  "id": "v4_hudiao", "kind": "stage", "year": 214, "order": 45, "age": [16, 70],
  "req": { "faction": "civ", "region": ["ji", "yu"] },
  "tag": "戶調", "title": "戶調", "text": "……",
  "note": "史料出處（介面上的小字「史」）",
  "choices": [ { "t": "選項", "req": {}, "show": {}, "lock": "條件不足時的說明", "eff": {}, "out": "結果" } ]
}
```

- `kind`：`anchor`（史實大事）、`stage`（人生階段與劇情）、`bond`（歷史人物羈絆）、`flavor`（隨機小事）。
- 有年份或年齡的 anchor／stage／bond 每年自動排入；沒有的只能由別的事件用 `later` 或 `next` 叫出來。
- `flavor`：用 `w` 權重、`p` 每年進候選的機率、`repeat` 一生可發生幾次。年齡要寫在 `req.age`（寫在外層會被忽略，稽核會報錯）。每年抽一到三件（多數年份兩件）。
- 有外層 `age` 的 stage 也可以寫 `p`：在年齡範圍裡每年只有 `p` 的機會觸發，範圍的最後一年一定輪到。用在與史實無關的人生抉擇（`events_life_choice.json` 的 `lx_*`），不會人人都在同一歲碰上。排入當年時就要符合條件；同一年最多一張，當年若已有兩張以上的大事抉擇（例如甲子年）就順延。
- 日常內容分檔：`events_life_child.json`（`lc_*` 童年少年）、`events_life_adult.json`（`la_*` 成年）、`events_life_old.json`（`lo_*` 中老年）、`events_life_choice.json`（`lx_*` 個人抉擇與後續）、`events_arc_focus.json`（`af_*` 依人生重心的故事線：行醫、行商、任俠、遊學、開荒、匠戶）、`events_arc_family.json`（`am_*` 家庭鄰里的故事線：夫妻失和、孩子婚事、遊俠少年、鄰家寡婦、娘家夫家、族長）。
- `alt`：同一段本文的其他寫法（任何 kind 都可以用）。從哪一種開始由這一局的種子決定，同一家族再碰到就換下一種，所以重玩的人不會每次都讀到同一句。不動用亂數，加寫法不會讓舊存檔走樣。
- 選項的 `tAlt` / `outAlt`：選項文字與結果文字的其他寫法，規則同 `alt`。 選項底下的小字也一樣：`subAlt` 是其他寫法，`subIf: [{ req, sub }]` 依條件換（例如女孩練武寫成女孩的樣子），`sub` 也可以是陣列。`textIf` 的 `text`、`outIf` 的 `out` 也可以直接寫成陣列。
- 選項的 `deathOut`：這個選項的 `risk` 當場致死時改用的結果文字（`out` 寫成活下來的選項一定要有，稽核會擋）。
- `world.json` 裡引擎套用的句子（`childText`、`heirText`、`nearlyLostText`、`mingyingText`、`plagueDeathText`、`heirWed*Text`、`mortality[].text`）也都可以是陣列。
- `group`（flavor 專用）：同一組一年只會發生一件，例如 `weather`（豐收、旱、澇、蝗）。
- `familyOnce`（flavor 專用）：整個家族只發生一次，例如祖上傳說（`pt_*`），不會每一代都講同一個故事。
- `textIf: [{ req, text }]`：依條件換開場，第一個符合的生效，都不符合就用 `text`。用在每一代都會碰到的人生大事（接家、四十、花甲），讓不同時代、不同家境讀起來不一樣。
- 選項的 `outIf: [{ req, out }]`：依條件換結果文字，例如「把本事傳給下一代」依人生重心寫醫術、讀書、跑商路或種田。
- `recheck: true`：用 `later` 排定的後續事件，到時候仍要符合 `req` 才發生（例如幾年後再來說媒，但人已經成親或發誓不嫁娶）。沒標的話，排定的事件不看條件。
- `campaign: true`：標記為上陣打仗；那一年家鄉的隨機小事不會發生（黃巾／官軍／義勇路線與限男子的陣營卡會自動算進來）。
- 選項：`req` 不符時顯示為鎖住（附 `lock` 說明）；`show` 不符時整個不顯示。`chk` 可做成功／失敗判定（`ok`／`fail` 各有 `eff` 與 `out`）。

### 條件 `req`

`age` `year` `chapter` `region` `noregion`（排除某些地區，例如外地人視角的小事不給住在洛陽的人）`cls` `gender` `faction` `route` `focus` `talent` `flag` `anyFlag` `noflag` `stat` `statMax` `bond` `bondMax` `married` `gen` `child` `son`

- `faction` 含 `civ` 時，身在曹、袁、黑山陣營的女性也算符合（她們不上陣，但也是當地百姓）；孫、劉兩家不適用。
- `married: true` 代表配偶此刻在身邊（喪偶、配偶被抓走未歸都不算）。
- `child: [最小, 最大]`／`son: [...]`：家裡要有這個年紀、還在身邊的孩子；文字裡用 `{kid}`／`{son}` 指那個孩子。加 `kidUnwed: true` 只挑還沒成親的孩子。
- `kidTag`：故事線的後續節點用，指定先前用 `eff.tagKid` 標記過的那個孩子（不看年齡），`{kid}`／`{son}` 就是那個孩子，家裡孩子多的時候不會認錯人。

### 效果 `eff`

`武` `文` `德` `名` `財` `健` `flag` `unflag` `route` `faction` `focus` `spouse`（`@random` 為隨機姓名）`bond` `injure` `risk` `die` `later` `child` `childDie` `childAway` `tagKid` `region`

- `childDie: true` 帶走家裡最小、還在身邊的孩子；寫字串則帶走 `tagKid` 標記過的那一個。
- `kidWed: true`：條件挑中的那個孩子成親了。這個孩子日後接家時，一定是已經成了家的人。
- 設定 `world.relocate` 裡列出的旗標會搬家；搬進吳、蜀地盤（在 `factionUntil` 之前）時，原屬別家陣營的人改為當地百姓。
- 地區：出生地有 `ji` `qing` `yu`（潁川、許昌）`jing`（南陽、襄陽一帶，208 年後屬曹魏）`you` `xu`（下邳），另有只能搬進去的：
  - `wu`（江東）、`shu`（蜀地）
  - `jiangling`（江陵：208 年後先屬劉備、219 年起屬吳、280 年歸晉）
  - `luoyang`（洛陽：曹丕遷冀州士家、潁川人修宮殿後留下）
  - `huainan`（淮南壽春：鄧艾屯田時遷入）

  規則：整個荊州的事件同時列 `jing` 和 `jiangling`，只發生在南陽、樊城的只列 `jing`；人一定要在洛陽城裡的只列 `luoyang`，聽說型的消息列 `yu` 和 `luoyang`；人一定要在建業的吳國卡只列 `wu`；壽春本地的事列 `huainan`，波及淮北的再加 `xu`。

### 文字變數

`{name}` `{friend}` `{region}` `{place}` `{age}` `{year}` `{era}` `{ta}`（玩家的他／她）`{self}` `{spouse}` `{child}` `{kid}` `{son}` `{parent}` `{prev}`（剛過世的上一任當家）`{elder}`（祖上傳說裡真正做過那件事的人）`{surname}` `{gen}`（第幾代，中文數字）

文字裡留下沒填的 `{變數}` 會被稽核抓出來。

## 結局 `endings.json`

由上往下找第一個符合的，所以**特殊的寫在前面、通用的寫在後面**，每一章都要有不帶條件的保底。

- `when`：`alive`（章末）或 `dead`（身故）；`chapter`：不寫代表不分章。
- `cause`：死因清單（例如 `["戰死", "兵禍"]`）。
- `noKid`：沒有孩子在世時改用的寫法（例如不能出現「孫子在床邊」）。
- `rare: true`：結局冊與結局頁標示「稀有」。
- `fallback: true`：保底結局（正常玩法幾乎遇不到，例如通用章末）。不算進結局冊的分母，也不佔「？？」的位置，真的遇到了才列出來。判斷方式：大量模擬（例如六萬局）都沒出現的才標。新增結局後如果它被前面的結局擋住而永遠拿不到，請調整順序，不要標成保底。
- 同一章、同一類（章末／身故）的標題不可重複，否則結局冊分不出來（稽核會提醒）。
- 結局冊的「人生故事」來自 `world.arcBook`：每條故事線一列，每格 `{ id, title, all?, any? }`，`all`（預設 `[id]`）的旗標都有、`any` 至少有一個，就算走到。章末與一生結束時記錄，結局頁會提示新收進的。稽核會檢查旗標有沒有地方設定、id 有沒有重複。
- 13 歲以下的人在章末會先拿到 `aN_child`（童年）。

## 後記 `world.epilogues`

- `final: true` 且沒有 `chapter`：**個人往事**，一個人的一生結束時顯示。只算這輩子親身經歷的旗標（從上一代繼承來的不算）。
- `final: true` 且有 `chapter`：天下的收尾，整個家族結束時顯示。
- 往事的時間修正：`minYears`／`short`（經歷之後沒活幾年時改用短版）、`aliveText`（活著走到最後一章）、`beforeYear`／`lateText`（文字講到的未來已經過去）、`noKid`。`pri: 1` 的往事排在前面（故事線的結局，例如行醫收徒、孩子的婚事、族裡分祭田），其餘照資料順序；結局頁先放三件，其他收起來。排第一的那件也記進家譜（`lineage[].memo`），家譜上每一代底下有一句往事；晚生開局自動跑過的祖上不留往事。

## 傳承相關設定（`world.json`）

| 設定 | 說明 |
|---|---|
| `inheritFlags` | 會傳給接班人的旗標（住在哪、全家做過的決定，例如 `dianke_done`） |
| `parentFlags` | 上一代的經歷，接班人得到 `p_` 開頭的旗標，用來觸發祖上傳說（`{elder}`） |
| `heirMarried`／`heirPastChildRate`／`heirPastChildSurvive` | 成年接班人已成家的機率、接班前每年添丁率、那些孩子養大的機率（影響難度） |
| `childChance` | 有配偶在身邊時每年添丁的機率 |
| `spouseMortality` | 配偶死亡率相對於玩家同齡死亡率的倍數 |
| `firstChildSpare` | 第一代主角五歲前死裡逃生的機率（還沒有弟妹時一定撐得過去） |
| `minChoiceAge` | 沒寫年齡的抉擇卡，預設要幾歲以上才會出現（年幼接班人不會被問要不要上陣） |
| `familyRepeatWeight` | 祖上經歷過的隨機小事，接班人再抽到的權重 |
| `plagueYears` | 疫年；數字為天下大疫，`{year, regions}` 為地區性疫病 |

## 投胎到家族的後代（`world.lateStart`）

`chance` 的機率（目前 0.3），投胎不是第一代：引擎先在背後用同一顆種子，從第一代開始把前幾代的人生真的跑一遍（隨機選擇），跑到 `years` 範圍內某一年、當家的人 18–40 歲又有配偶在身邊時，玩家出生成為他的孩子。祖上的家譜、章末、傳說（已過世那幾代的 `p_` 旗標）、住處、家世與勢力都會傳下來；當時已經出生的孩子成為玩家的兄姊。

是不是後代投胎由介面在開新局時決定，記在存檔的 `late` 欄位。舊存檔沒有這個欄位，照第一代處理。

接班時未滿 14 歲的人會帶 `heir_young` 旗標，長大後改看 `st_heir_focus_young`。

## 稽核會擋下的事（`sim.js`）

靜態檢查：事件引用、旗標「有設沒讀／有讀沒設」、未知的欄位、每章保底結局、文字變數、結局標題重複、flavor 外層年齡、年齡上不可能達到的結局（例如要 55 歲以上，但那一章最老的人只有 48 歲）。

結局由上往下找第一個符合的，不分章的通用結局（`d_young` 早逝、`d_old` 壽終）也在清單裡。新增某一章專屬的年齡結局時，要放在這些通用結局的前面，否則永遠輪不到。

執行時一致性檢查（過去實際出過的問題）：
- 父母已過世又收到過世的消息；孩子接班時死去的父或母沒記為已過世
- 配偶已過世還收到要求配偶在身邊的卡
- 出征那年還發生家鄉小事
- 同一年兩件天氣小事
- 「孩子沒能熬過冬天」帶走的不是幼兒
- 沒有孩子在世，結局或往事卻寫到自家孩子
- 全家一起決定的事被接班人又決定一次（清單在 `sim.js` 的 `HOUSEHOLD`）
- 已經寫了「終」（壽終、病逝）人卻又活過來（命硬那一年改寫 `world.mingyingIllText`「病倒了」）
- 孩子跟配偶同名同姓、或用了父母的名（犯諱）；取名在引擎的 `kidName`、`spouseName`
- 孩子成親過，接家時卻是單身
- 已經成親、或說過再也不嫁娶的人，又有人來說媒
- 年幼接班的人十五、十六歲連續選兩次人生重心

新增這類規則時，最好也把對應的檢查加進 `sim.js`，並故意把資料改壞一次，確認檢查真的抓得到。

## 意見回饋

結局頁有「到 GitHub 回饋」（開一則預先填好的 Issue）與「複製這一局的資訊」（給沒有 GitHub 帳號的人貼到 LINE 等地方）。內容包含內容版本、種子、是否後代投胎、人物與結局、裝置，以及存檔碼。

「到 GitHub 回饋」開的是 `.github/ISSUE_TEMPLATE/feedback.yml` 這份表單（分類、想說的話、這一局的資訊），會自動加上「回饋」標籤。

**版本號**：打包時寫入「建置日期＋git 提交號」，顯示在首頁說明文字的最後，也附在回饋裡。提交號後面有「+」代表打包時還有沒提交的修改；要發佈的版本請先提交再打包。存檔碼要用同一個版本重播，劇情才會一模一樣。

**重現玩家看到的劇情**：在首頁的「換裝置：存檔碼」貼上回饋裡的存檔碼、按「讀入」，再按「接續」，就會照著玩家的選擇重播到同一個結局（家族結束時存檔會被清掉，回饋裡的存檔碼是清掉前留下的那一份）。

## 背景音樂

沒有音檔，全部在瀏覽器裡當場合成（`ui.html` 的 `music`）：撥弦音（Karplus-Strong）在 D 宮五聲音階上隨機小步走，底下兩個很輕的低音持續音，再加一點延遲殘響。所以沒有版權問題，也不增加檔案大小。預設關閉，開關在開場頁與播放列（♪），選擇記在 `sg_music`；開過的人下次點畫面任何地方就接著響（瀏覽器規定聲音要等使用者先操作）。切到別的分頁會自動暫停。

## 存檔與收集（瀏覽器 localStorage）

- `sg_save`：`{ v, ver, seed, name, acts }`。只存種子和每一步操作（`['c', 選項]`、`['h', 接班人]`、`['n']`），接續時重播。內容改版後仍可接續，重播到對不上的那一步就交還給玩家。
- 接續時整段紀錄先在記憶體組好、不播淡入動畫，紀錄區只有最後 12 條會立刻排版，其餘用 `content-visibility: auto` 延後。瓶頸是瀏覽器替幾百條中文段落排版，不是引擎重播（重播 77 步約 30 毫秒）。
- `sg_seen`：見過的結局 id（結局冊），以及走到過的人生故事（`arc:` 加上 `world.arcBook` 的 id）。
- `sg_bonds`：每位人物達到過的最高交情。
- 存檔碼（首頁「換裝置」）：`HTZX1.` 加上 `{ s: sg_save, e: sg_seen, b: sg_bonds }` 的 base64（UTF-8）。讀入時只收真的結局與人物（交情限制在 0 到最高一級），結局冊取聯集、人物交情取較高者；進行中的家族換成存檔碼裡的，若這台裝置另有沒玩完的家族會先提醒一次。
- `sg_tips`：看過新手提示（第一次開局時顯示，按「知道了」才開始走）。
- `sg_speed`：播放速度（預設 1 倍）；`sg_theme`：`dark`（黑底）或 `light`（原色底），沒選過就跟著系統。
